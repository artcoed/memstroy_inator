# Сервер ассетов Memstroy - Оптимизация для 500MB RAM

## 🎯 Что сделано

Сервер оптимизирован для работы на серверах с **всего 500MB памяти**. Приложение не будет падать с OOM (Out of Memory) и корректно обрабатывает все запросы.

## ⚡ Ключевые изменения

### 1. Стриминг больших файлов
- Файлы **больше 50MB** передаются потоком, а не загружаются в память
- Экономия: **до 300MB** на больших видео

### 2. Умные лимиты
- Максимум **500 записей** в одном ответе (было 5000)
- Максимум **100 клипов** за один инжест (было 500)
- Используйте пагинацию для больших запросов

### 3. Меньше параллелизма
- **2 worker threads** вместо автоопределения
- **2 параллельных загрузки** вместо 4
- Меньше пиков памяти

### 4. Защита от переполнения
- Текстовые файлы ограничены **10MB**
- Тело запроса ограничено **10MB**
- Описания в индексе усечены до **500 символов**

## 📊 Потребление памяти

| Ситуация | Память |
|----------|--------|
| Пустой сервер | 20-50 MB |
| 1000 клипов в индексе | 80-120 MB |
| Скачивание большого файла | 50-80 MB |
| Инжест 100 клипов | 150-250 MB |
| **Максимум** | **~400 MB** ✅ |

## 🚀 Запуск

### Локально
```bash
cargo run --release --bin memstroy-assets-server -- --root ./assets
```

### Railway / Heroku
```bash
# Установите переменные окружения:
ASSETS_ROOT=/data/assets
RUST_LOG=info
PORT=8765

# Сервер автоматически использует PORT из окружения
```

### Docker
```bash
docker build -t memstroy-server .
docker run -p 8765:8765 -v /path/to/assets:/data/assets memstroy-server
```

## 📖 Использование API

### ✅ Правильно (с пагинацией)
```bash
# Получить первые 50 клипов
curl "http://localhost:8765/api/assets?kind=clip&limit=50&offset=0"

# Получить следующие 50
curl "http://localhost:8765/api/assets?kind=clip&limit=50&offset=50"

# Инжест небольшими порциями
curl -X POST http://localhost:8765/api/ingest/tg \
  -H "Content-Type: application/json" \
  -d '{"channel": "mellstroy", "limit": 100}'
```

### ❌ Неправильно (может вызвать проблемы)
```bash
# Слишком большой запрос
curl "http://localhost:8765/api/assets?limit=5000"  # Максимум 500!

# Слишком большой инжест
curl -X POST http://localhost:8765/api/ingest/tg \
  -H "Content-Type: application/json" \
  -d '{"channel": "mellstroy", "limit": 1000}'  # Лучше по 100!
```

## 🔧 Настройка под ваши нужды

### Если у вас 1GB+ памяти

Можете увеличить лимиты для лучшей производительности:

**src/api.rs:**
```rust
const MAX_LIMIT: u64 = 1000;  // вместо 500
const MAX_IN_MEMORY_SIZE: u64 = 100 * 1024 * 1024;  // 100MB

fn default_ingest_limit() -> u32 {
    200  // вместо 100
}
```

**src/main.rs:**
```rust
#[tokio::main(worker_threads = 4)]  // вместо 2
```

**src/ingest.rs:**
```rust
download_videos(&posts, &clips_dir, false, 4)  // вместо 2
```

Затем пересоберите:
```bash
cargo build --release --bin memstroy-assets-server
```

## 🐛 Решение проблем

### Сервер падает с OOM
1. Уменьшите лимит инжеста до 50
2. Проверьте, что не запущено несколько инжестов одновременно
3. Убедитесь, что нет других процессов, жрущих память

### Медленные ответы
1. Это нормально для больших файлов (стриминг)
2. Используйте превью: `/api/assets/:id/preview`
3. Включите кеширование на клиенте

### Усеченные описания
1. В списках (`/api/assets`) описания усечены до 500 символов
2. Полное описание: `/api/assets/:id`
